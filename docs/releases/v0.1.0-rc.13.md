## 本次更新

### 项目更名为 OpenCode Lagoon（与 GitHub 仓库名对齐）

本次唯一改动是把应用与工程身份从 “OpenCode Mobile” 彻底更名为 “OpenCode Lagoon”，
没有任何功能或界面行为变化；改名原因是原名与多个第三方 OpenCode 客户端和上架应用撞名。

- **应用显示名**变为 `OpenCode Lagoon`，主题、日志标签、安装包名（`OpenCode-Lagoon-<version>.apk`）一并更新。
- **应用包名** `applicationId` 变为 `com.igng.opencode.lagoon`。⚠️ 这是本次唯一影响安装的改动：
  新旧包名在 Android 上是两个独立应用，**本包不会覆盖升级旧的 OpenCode Mobile**，
  需要先在旧 App 里记下服务器地址与配对链接，安装本包后重新录入（旧包的密码、Cookie、
  离线缓存不迁移，Android Keystore 按包名隔离，本身也无法跨包读取）。
  两个包共用同一张签名证书，因此将来若决定把包名改回，签名身份仍是连续的。
- **深链接 scheme** 改为 `opencode-lagoon://`，App 内通知点按跳转随之内联更新，旧包的链接不会被本包接住。
- **代码包路径** `com.igng.opencode.lagoon.*`，核心控制器与 FCM 服务类随之改名（`LagoonController`、
  `LagoonState`、`LagoonMessagingService`），不影响运行时行为。
- **companion 与 OpenCode 插件契约改名**：插件文件 `opencode-lagoon.plugin.js`、
  环境变量前缀 `OPENCODE_LAGOON_*`、入站头 `x-opencode-lagoon-secret`、
  状态目录 `~/.local/state/opencode-lagoon/`。已有 companion 部署需要先
  `mv` 旧状态目录到新路径再改环境变量，否则已注册设备与待发队列会丢失。
  本次发布不涉及服务端升级：已核查的本机与 nas / pve1 / ubuntu-vm / ubuntu-mc 上都没有
  在跑的 companion 进程、旧状态目录或已安装插件。
- **发布链路改名**：CI Secrets 与 keystore 别名改为 `OPENCODE_LAGOON_*` / `opencode-lagoon-release`，
  证书与指纹保持不变。
- **不含 FCM**：本次构建未注入 Firebase 配置（`OPENCODE_LAGOON_FIREBASE_CONFIG_BASE64` 未设置），
  因此本包不含可靠后台推送能力；服务器地址可用，前台 SSE 与系统通知正常。
  包名变更后需要在 Firebase 项目里为 `com.igng.opencode.lagoon` 重新添加 Android 应用，
  再配置该 Secret 才能启用 FCM。

- **未在实体设备上验收**：安装/卸载迁移路径（旧包 → 新包并存）、深链接跳转、

  `workstation` / `pve3`（SSH 认证失败）与 `ubuntu-ai` / `ubuntu-test`（无法连通）未能核实，
  若这些设备上曾部署 companion，需要按上面的 `mv` 步骤迁移后再升级插件文件。
- 仓库 CI 的「companion 测试」步骤存在间歇性挂起（与本次改名无关，本地复现一次、
  main 与 PR 的 run 各卡过一次），由仍在评审的 PR #27 处理。
